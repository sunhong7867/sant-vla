## 2. 서빙 계층 장애물 회피 (chat_gui `_avoid_check`)

열쇠는 기존 자산: **best_cap.pt가 차선별 차량 클래스(lane1_car/lane2_car)를
이미 학습**해 두었고(클래스 확인: `YOLO('best_cap.pt').names`), 코퍼스의
ring-lane 반사실 그룹 덕에 **정책이 문장만 바꾸면 차선을 옮기는 행동을
이미 안다**. 따라서 회피 = "내 차선 클래스 감지 → 문장 교체" 감독이면 되고,
실제 조향 기동은 VLA 자신이 수행한다.

상태기계 (YOLO 프레임마다, cruise/zone 모드에서만):

```
CRUISE ─(지시 차선의 *_car bbox 높이 ≥ avoid_trigger_px(48px)
         × avoid_hits(2프레임 연속), 쿨다운 6s 경과)→
  차선 플립 + cruise 문장 재발행(브리지가 큐 flush) → AVOID
AVOID ─(원래 차선 *_car가 avoid_clear_s(4s) 미감지
        AND 회피 후 avoid_min_hold_s(8s) 경과)→ 원래 차선 복귀
```

- min_hold가 필요한 이유: 장애물 옆을 지나는 동안 카메라 FOV에서
  사라져 clear 판정이 너무 일찍 나기 때문.
- 사용자 새 명령은 회피 상태를 즉시 폐기(원래 차선 복원 없이 — 사용자가
  차선을 재정의 중이므로). idle/direct 전환 시엔 원래 차선 복원.
- `avoid_enable:=false`로 끔. 회피/복귀 시 채팅창 알림.

같이 바꾼 것:

- `smolvla_demo.sh`: YOLO `allowed_class_names`에 lane1_car/lane2_car 추가
  (기존엔 차선만 통과 — 차량 검출이 버려지고 있었다).
- `scene_facts`: 장애물 필터 `startswith("lane")` → `{"lane1","lane2"}`
  제외로 교체 (lane1_car가 장애물로 잡히도록). 해설 표기는
  "1차선 전방 차량"으로 번역.
- `tools/spawn_avoid_obstacle.py`: track_paths.json 웨이포인트 위에 진행
  방향으로 hatchback 스폰(회색 큐브는 best_cap이 모르는 물체라 대체).

```bash
# 재현: 데모 기동 → VLA 주행 → 장애물 스폰 → 회피/복귀 관찰
python3 tools/spawn_avoid_obstacle.py --lane lane2 --frac 0.25
python3 tools/spawn_avoid_obstacle.py --remove
# 트리거 튜닝: 로그의 detection bbox h를 보고 avoid_trigger_px 조정
```

**미검증**: 폐루프 실주행은 아직 안 돌림. avoid_trigger_px=48px(≈10~15m
추정)과 min_hold=8s는 첫 주행에서 실측 튜닝 필요.

### 17:5x 추가 — 3차 시험: 감지가 충돌 0.5s 전 + 재플립 충돌, 수정 2건

실주행에서 (a) 감지 메시지가 충돌 직전에야 뜨고, (b) 메시지 순서가
"회피 → 회피 차선에도 장애물 → 즉시 복귀"로 **원래 장애물 차선으로

없어, 회피 조향 중 아직 시야에 남은 원래 장애물을 "회피 차선의 새
장애물"로 오인.

1. **조기 감지 — 단계형 질의로 교체.** "직진하면 부딪치나"(늦게 True)
   대신 `{obstacle_on_road, in_my_path, distance}` 스키마: 충돌 접근
   시퀀스에서 in_my_path가 **프레임 10부터 True**(기존 13 → ~3s 조기),
   클리어 프레임 오탐 0, 도형도 잡힘(70은 in_my_path=false 판정 — 완벽
   아님). 추가로 avoid_vlm_period 1.0→0.6s, 프레임 신선도 2.5→1.0s.
2. **재플립 제거 — 회피 중 재차단은 정지.** AVOID 상태에서 blocked면

   차선 그대로 slowly 재출발(새 commit 윈도). 진짜 이중 차단이어도
   정지가 안전한 결말이고, 사용자가 채팅으로 재지시 가능.

### 18:1x 추가 — 4차 시험: 장애물 있는 차선으로 회피 → 차선 귀속을 좌표로

4차 실주행: 2차선 주행 중 1차선 장애물을 보고 **1차선으로** 회피. 원인은

- same/other 차선 질의: 실프레임 9장 전부 'same' (인접 차선 3장 포함).

최종 아키텍처 = **역할 분리**: VLM은 "도로에 장애물이 보이는가+거리감"만
(이건 벤치마크 전 구간 정확), **어느 차선인지는 좌표가 판정** — 스폰
레지스트리(obstacles.json: 데모 스폰 블록/spawn_avoid_obstacle.py가 기록,
track_paths 최근접으로 lane 라벨) + ego gz ground-truth(`query_world_pose`,
VLM 감지 시에만 ~150ms 1회, navigator 존 감시와 같은 인프라). 판정:
전방 70° 콘 안 avoid_range_m(18m) 내 최근접 레지스트리 장애물의 lane ==
지시 차선 → blocked. 다른 차선이면 회피 안 함. 레지스트리/포즈 불가 시
폴백 = VLM distance:near에서만 반응. 부수 효과: 회피 조향 중 원래
장애물 재목격으로 인한 헛정지도 사라짐(그 장애물 lane ≠ 새 지시 차선).
