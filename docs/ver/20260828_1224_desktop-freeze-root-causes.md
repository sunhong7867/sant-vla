# 2026-08-28 12:24 — 데모 중 데스크톱 프리즈(강제 전원종료) 원인 4중과 수정

노트북(14G RAM / RTX 8G)에서 SmolVLA 데모 실행 중 화면·마우스가 30분+ 멈춰
강제 전원종료. 원인은 하나가 아니라 네 겹이었고, 전부 실측으로 확인 후 수정.

## 원인과 수정 (기여 큰 순)

1. **RAM 총고갈 + 스왑 4G 소진** (실측 14/14G, 가용 445MB) → 스왑 스래싱 =
   입력 불능 프리즈. 스택 합계(gz 2.5 + torch 서버 3 + ollama 4b 상주 2 +
   YOLO 1.5 + 기타 1 + IDE/브라우저 4+)가 14G 초과.
   - 수정: ollama keep_alive ∞→15m(유휴 시 RAM 2G/VRAM 3.2G 반환),
     smolvla_demo.sh에 **가용 RAM<6G면 기동 거부** 프리플라이트.
   - 권장(미실행): 스왑 4G→12G 확장(sudo 필요).
2. **/clock 943 Hz** — gz 1kHz 물리 스텝을 클록 브리지가 전부 중계 →
   use_sim_time 노드 전원의 executor가 초당 ~1000회 기상.
   - 수정: 브리지를 /clock_raw로 리맵 + `clock_throttle_node`(신규,
     simulation_pkg)가 /clock 100Hz 상한 재발행. 실측 43Hz, 카메라 12→20Hz.
3. **vla_bridge가 유휴에도 코어 1개(99%)** — rclpy MultiThreadedExecutor의
   busy-wait(Jazzy 알려진 문제). 콜백은 전부 1ms 미만(JPEG 인코드 실측
   1.0ms), 추론은 별도 스레드라 MTE가 필요 없었음.
   - 수정: 단일 스레드 spin으로 교체 → 유휴 25%. (참고:
     episode_recorder_node도 MTE 사용 — 수집 세션에서 같은 검토 필요)
   - 추가: 추론 루프 5ms 스핀→20ms.
4. **해설 LLM 매초 생성** — qwen3:4b 상주+연속 생성 = CPU 1코어 + GPU 점유.
   - 수정: 상황 변화/4초 하트비트에만 생성으로 게이트. 그리고 실측 결과
     0.6b는 품질 미달(프롬프트 에코), 4b는 노트북에 과중 → **노트북 기본값
     = LLM 해설 OFF(동적 템플릿만)**, `scene_model` 파라미터로 옵트인.
     고품질 LLM 해설은 랩서버 3090에 ollama를 올려 HTTP 오프로딩이 정석
     (서버 GPU 유휴 확인, 미구축).
