# 오프라인 한 모델 두 동작: 잘되던 방식 (gcf300) 그대로 + 입력 속도 · 조향각 E (사전 등록)

## 왜
- 앞의 네 섞인 모델 (2차선 + 물체 3 개 한 모델) 은 고르기가 모두 16 ~ 21/120 이었다.
- 이 모델들은 이름 고르기가 되던 gcf300 (112/120) 방식에서 여러 가지를 한꺼번에 바꾼 것이었다:
  - 학습량: batch 8 × 10k → batch 4 × 6k (물체 샘플 약 8 만 → 약 1 만).
  - 상태 입력: 속도 · 멈춰 있던 시간 → 전부 0.
  - 문장: 물체마다 고정 문장 5 개 (`--name-tasks`) → 수집 때 문장 35 개.
  - 학습 경로: 서버 일반 학습 (`tools/train_ground.py`) → T4 흉내 경로 (`train_fp16.py` + `colab/train_ground.py`).
- 사용자 지시 (11-17): 잘되던 방식 (한 프레임에 원래 문장 + 이름 바꾼 문장 = 반사실 이름 손실) 그대로 학습하고, 입력은 **속도와 조향** 을 넣는다.

## 모델

| 이름 | 무엇 |
|---|---|
| **E** `lane2+pick3-namecf-speedsteer-20laps150ep` | gcf300 학습 경로 그대로 (`tools/train_on_server.sh` + `tools/train_ground.py`, 반사실 이름 W 0.5, batch 8 × 10,000 step, 시드 1000, `--name-tasks`). 데이터는 앞과 같은 170 ep (2차선 20 + 물체 150, 물체마다 30). 입력 = 속도 + 조향각 (`--steer-in-yaw`: 직전 명령의 앞바퀴 각도, stop1-steer 와 같은 방식) |

- 0 으로 두는 칸: 라이다 앞 거리 · 목표 방위 · 목표 거리 · 멈춰 있던 시간.
- gcf300 과 다른 점은 이제 두 가지만 남는다: (1) 차선 데이터 20 ep 가 섞임, (2) 상태 입력이 속도 + 조향각 (gcf300 은 속도 + 멈춰 있던 시간).
- 서버 3090 한 장 (GPU 1). 서버 디스크 여유 8 GB 라 체크포인트를 하나만 둘 수 있어 한 모델만 돌린다.
- T4 한도 (batch 4) 는 이번에 지키지 않는다. 되면 T4 시간 문제는 따로 푼다.
- 조향 제한 없음 (앞과 같음, `COURSE_STEER=diff`).
- 평가 때 정책 노드는 `state_steer:=true` (조향각 칸에 직전 명령 앞바퀴 각도).
