# 실습 점검: 온라인 · 오프라인 실습을 학생 방식대로 수집 → Colab 전체 학습 → 실행 (사전 등록)

2026-11-16 10:57 · 사용자 요청: "이제 실제 실습이 가능한지 확인이 필요한 단계. 온라인 실습, 오프라인 실습용 둘 다. 둘 각각 학습하고 실행해 보는 거 가능하도록 ros2_vla 에 반영. 학습할 때 전체 학습, 문장 넣어서. 학생들이 직접 문장을 작성하고 수동주행해서."

## 한눈에 보기
- **온라인 실습 (시뮬):** 1 · 2차선 주행과 차선변경.
- **오프라인 실습 (실제 트랙, 지금은 시뮬로 먼저):** 2차선 주행과 물체 이동. 시뮬과 실차가 같은 코드를 쓴다.
- **학습:** Colab 무료 T4 에서 SmolVLM2 + Action Expert **전체 학습**. 학생이 쓴 문장이 언어 쪽까지 학습된다.
- **확인할 것:** 과정마다 "수집 → zip → Colab 학습 → 모델 받기 → 노트북에서 실행" 이 끊기지 않는가, 그렇게 만든 모델이 과제를 하는가.
- 사람 수동주행 대신 **오라클 (시뮬 정답 운전)** 로 모은다. 학생 수동주행의 질은 이 점검에서 재지 않는다.

## 1. ros2_vla 에 바꾼 것 (11-16)

| 곳 | 바꾼 것 |
|---|---|
| `commands.py` | `COURSES`: 과정마다 문장 묶음 · 물체 칸 유무 · 오라클 작업 · 에피소드 폴더 · 학습 때 0 으로 둘 상태 칸 · 시험 문장 |
| 수집 GUI `collect_studio --course` | 과정 문장 묶음만 보임 (문장은 직접 써도 됨), 온라인은 물체 칸 없음, 오라클에 1차선 바퀴 · 차선변경 바퀴 추가, 오프라인 오라클은 물체 1 개 + 이름 문장 (물체를 차례로 돌려 같은 수) |
| 기록기 | 과정 폴더 (`data/episodes_online` · `data/episodes_offline`), meta 에 `course`, 실차는 오도메트리 없이 녹화 (속도 칸 0) |
| 변환 `convert_to_lerobot.py` | meta 의 과정을 보고 상태 칸을 저절로 0 으로. 두 과정이 섞이면 멈춤 |
| `train_fp16.py` | 전체 학습이면 모델 원본을 fp32 로 두고 계산만 fp16 (T4 는 bf16 이 없다) |
| Colab 노트북 | 기본을 전체 학습 · batch 4 · 6,000 step 으로. Expert 만은 선택 |
| `pack_for_colab.py --course` | 과정 폴더를 묶음. 요약에 학생이 쓴 문장을 그대로 보임 |
| `ros2vla.sh` | `collect --course X [--real]`, `up --course X --model M [--real]` (`--real` = 시뮬 안 띄움) |
| 평가 도구 | `check_lane_laps.py --lane 1`, 새 `check_lane_change.py` |

**상태 입력**
- 온라인 = 속도 + 멈춰 있던 시간 (lane2-speed-standstill 구성, 2차선 10/10 · 11-12).
- 오프라인 = 없음. 실차에는 엔코더 · 위치가 없다. 상태 없이도 2차선 10/10 (lane2-nostate-30laps) · 물체 앞 서기 59/60 (stop1-nostate-50) 이 나왔다 (11-12).

**Colab 전체 학습이 T4 에 들어가는지 (서버에서 흉내, 11-16)**
- 3090 에서 쓸 수 있는 메모리를 14.7 GB 로 묶고 돌렸다: batch 8 은 메모리 부족, **batch 4 는 됨** (0.32 s/step).
- 수 형식 비교 300 step (lane2-30laps 데이터, batch 8): 원래 bf16 loss 0.028 · 0.47 s/step, fp32 원본 + fp16 계산 loss 0.036 · 0.55 s/step. 같이 내려간다. fp16 쪽은 손실 배율을 맞추는 처음 몇 step 을 건너뛴다.
- **T4 에서의 실제 속도는 재지 못했다** (Colab 에 들어갈 수 없음). 3090 보다 느리다.

## 2. 점검 모델

| 새 이름 | 과정 | 데이터 (오라클) | 문장 |
|---|---|---|---|
| **drive-colab-30laps** | 온라인 | 2차선 10 바퀴 + 1차선 10 바퀴 + 차선변경 10 바퀴 (바퀴마다 두 번 바꿈 = 20 번) | 바퀴마다 그 차선 묶음의 [학습] 표현을 차례로 (2차선 10 개, 1차선 5 개) |
| **lane2+stop1-nostate-colab-20laps50ep** | 오프라인 | 2차선 20 바퀴 + 물체 1 개 앞 서기 50 번 (5 종 × 10) | 2차선 = 차례로, 물체 = `Go to the <이름>.` |

- `colab` = Colab 노트북 그대로: 변환 `--trim-still --keep-after 10`, `train_fp16.py` 전체 학습, batch 4, 6,000 step, 시드 1000.
- 학습은 연구실 서버 3090 에서 하되, 메모리를 14.7 GB 로 묶어 T4 와 같은 한도로 돌린다.
- 실행은 노트북 (RTX 4060 8 GB) 의 `scripts/serve.sh` 로 한다 (학생이 받은 모델을 노트북에서 돌리는 길과 같다).
- 모델 하나로 과정의 두 과제를 함께 한다. 학생이 Colab 학습을 과정마다 한 번만 하면 되게.

## 3. 평가와 기각선 (실행 전 고정)

| 모델 | 시험 | 통과 | 기각 | 사이 |
|---|---|---|---|---|
| drive-colab-30laps | 2차선 1 바퀴 (출발선 5 + 무작위 5, `check_lane_laps.py`) | 9/10 이상 | 6/10 이하 | 결론 없음 |
| drive-colab-30laps | 1차선 1 바퀴 (같은 방식, `--lane 1`) | 9/10 이상 | 6/10 이하 | 결론 없음 |
| drive-colab-30laps | 차선변경 10 번 (2 → 1 다섯, 1 → 2 다섯, `check_lane_change.py`) | 8/10 이상 | 5/10 이하 | 결론 없음 |
| lane2+stop1-nostate-colab-20laps50ep | 2차선 1 바퀴 10 번 | 9/10 이상 | 6/10 이하 | 결론 없음 |
| lane2+stop1-nostate-colab-20laps50ep | 물체 1 개 앞 서기 60 번 (`check_name_goto.py --k 1 --scenes 30`, 학습 문장 30 + 시험 전용 문장 30) | 48/60 이상 | 30/60 이하 | 결론 없음 |

- 차선 시험 문장 = `Drive in lane N at normal speed.` (두 차선 묶음 모두 [학습] 첫 표현).
- 차선 이탈 = 그 차선 중심선에서 1.6 m 넘게. 차선변경 성공 = 바꾸라는 문장 뒤 20 초 안에 새 차선 중심선 0.8 m 안에 들어가 5 초 머묾. 바꾸기 전 8 초 동안 출발 차선 0.8 m 밖이면 실패 (먼저 바꿈 · 흔들림).
- 물체 앞 서기 성공 = 섰고, 물체가 정면 15° 안, 앞 간격 −1 ~ +1 m (지금까지와 같음).

**길 점검 (통과 / 실패만)**
1. 수집 GUI `--course online` · `--course offline` 이 과정 폴더에 `course` 가 적힌 에피소드를 남긴다.
2. `pack_for_colab.py --course` zip 을 노트북 명령 그대로 변환하면 상태 칸이 과정대로 0 이 된다.
3. T4 한도 (14.7 GB) 로 6,000 step 이 메모리 부족 없이 끝난다.
4. 받은 모델이 노트북 `scripts/serve.sh` 로 뜨고, `ros2vla.sh up --course X --model M` 의 테스트 GUI 문장 목록이 과정 시험 문장이다.

## 4. 예상 (실행 전)
- 온라인 2차선 · 1차선은 통과할 것 같다. 1차선은 굽이가 더 급하고 오라클도 굽이에서 최대 0.67 m 벗어나 (11-16 시험 수집) 2차선보다 어렵다.
- 차선변경은 결론 없음 쪽일 것 같다. 이 데이터 구성 (문장 바꿈 20 번) 으로 학습한 적이 없다.
- 오프라인 2차선은 통과, 물체 앞 서기는 결론 없음일 것 같다. 차선과 물체를 한 모델에 합친 lane2+pick3-30laps-60 (lo) 은 물체 3 개 중 고르기가 48/120 으로 깎였다. 이번은 물체 1 개라 고르기가 없지만, 학습량이 batch 4 × 6,000 으로 그동안 (batch 8 × 15,000) 의 1/5 이다.

## 5. 다음 단계 (결과 전 고정)
- **모두 통과:** 학생 실습 경로로 확정. 남는 것은 T4 실제 속도 (사용자가 Colab 에서 한 번 재야 함) · 학생 수동주행 데이터 · 실차 연결 (카메라 · 라이다 · 모터 노드).
- **차선은 통과, 차선변경 · 물체가 기각 또는 결론 없음:** 같은 데이터로 step 을 12,000 으로 늘려 본다 (학습량 문제인지). 그래도 안 되면 과제마다 모델을 나눈다.
- **차선부터 기각:** batch 4 × 6,000 이 부족한 것으로 보고 12,000 · 24,000 으로 가른다. Colab 시간 한도와 맞는지 같이 따진다.
