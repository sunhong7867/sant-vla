# 우리 파인튜닝 방식 정리 — 2단계 학습과 회피 실험 설정 (2026-10-03 10:14)

관련: [VLA 문제점과 해결책 F절](20261003_0958_vla-failure-modes-and-fixes.md) · [r46](20261002_1857_r46-pair137-result.md) · [종합표](20261002_1354_avoidance-models-summary.md)

## 0. 요약

- **2단계 파인튜닝**이다. LoRA 같은 어댑터가 아니라 **파라미터를 직접 업데이트**한다.
- **1단계 (베이스, v3y)**: `lerobot/smolvla_base`에서 시작해 **비전 인코더까지 포함한 전체 파인튜닝**을 한다. 손실은 행동(flow matching)만 쓴다.
- **2단계 (추론 공동학습, r1~r47)**: 1단계 체크포인트에서 시작한다. **비전 인코더는 고정**하고, 언어 모델과 행동 전문가는 낮은 학습률로, 새 추론 헤드는 높은 학습률로 학습한다. 손실은 행동 + 추론 문장 CE다.
- 회피 실험(r38~r47)은 모두 2단계 레시피로 학습했다. 시작점은 주행 데모 모델 **r26**이다.
- 시사점: 장애물을 가르치는 2단계에서 비전 인코더가 고정이라, **박스를 보는 능력이 1단계(장애물이 거의 없는 주행 데이터) 수준에 묶여 있다**. 장애물 반응이 약한 원인 후보다(F절 20·22번).

## 1. 1단계 — 베이스 주행 학습 (v3y)

| 항목 | 값 |
|---|---|
| 스크립트 | `server/code/train_smolvla.sh` (LeRobot `lerobot-train`) |
| 시작점 | `lerobot/smolvla_base` (Hugging Face 사전학습) |
| 학습 범위 | **전체**: `--policy.freeze_vision_encoder=false`, `--policy.train_expert_only=false` → 비전 인코더 포함 약 403M 학습 |
| 카메라 | 전방 1대. smolvla_base는 3대 기준이라 `--rename_map`으로 `front → camera1`, `--policy.empty_cameras=2`로 나머지 2대는 빈 이미지 |
| 행동 청크 | `chunk_size=30`, `n_action_steps=30` |
| 배치 / step | 배치 8 (32는 3090 24 GB 초과), 기본 40000 step, 저장 5000마다 |
| 정밀도 | AMP (`use_amp=true`) |
| 손실 | flow matching (행동) |
| 데이터 | v3y 주행 코퍼스 (속도 단계 70/150/200, 순항 지시) |
| 산출 | `runs/navvla_smolvla_v3y` |

비전을 풀어 둔 이유는 스크립트 주석에 있다.
- 비전을 고정하고 행동 전문가만 학습하면 몸통이 실외 주행 도메인에 적응하지 못한다.
- 그 상태에서는 언어가 장식이 된다. 코퍼스 자체가 이 실패를 피하려고 만든 것이다.
- "VRAM 때문에 고정해야 한다면 그건 보고할 결과이지 기본값이 아니다"라고 적혀 있다.

## 2. 2단계 — 추론 공동학습 (r1 → … → r26 → r38~r47)

| 항목 | 값 |
|---|---|
| 스크립트 | `server/code/train_reasoning.py` (직접 만든 루프. `lerobot-train`은 손실을 두 개 둘 수 없음) |
| 정책 클래스 | `ReasoningSmolVLAPolicy` (`reasoning_vla/reasoning_policy.py`), SmolVLA + 추론 헤드 |
| 시작점 | 1단계 v3y 체크포인트. 회피 실험은 **r26**(v3y 위에서 학습한 추론 모델, 주행 데모 기본 서빙) |
| 비전 인코더 | **고정** (`train_reasoning.py:193`, `cfg.freeze_vision_encoder = True`, "1단계에서 이미 적응") |
| 언어 모델 + 행동 전문가 | 학습, `--lr-trunk 1e-5` |
| 추론 헤드 | 학습, `--lr-head 5e-5` (새로 붙인 부분이라 빠르게) |
| 손실 | flow matching + `ce_weight` × 추론 문장 CE (기본 0.1, 회피 실험 0.2) |
| 옵티마이저 | AdamW, betas (0.9, 0.95), weight decay 1e-10, grad clip 1.0 |
| 학습률 일정 | 워밍업 250 step → 코사인으로 0.1배까지 |
| 배치 | 8 |
| 정규화 | 학습 데이터셋 자체의 통계 (lerobot-train과 같은 방식) |

추론 헤드에 관한 주의점:
- 코드 주석에 따르면 **행동 전문가는 추론 토큰을 읽지 않는다**. 해설이 장애물을 말해도 그 정보가 행동으로 가는 경로가 구조적으로 없다.
- 그래서 r40부터는 `--situation-prompt`로 상황 문구를 지시문 뒤에 붙인다. 서빙에서는 `--situation-from-reasoning`으로 같은 경로를 쓴다. 이것이 인지 분리형의 학습 쪽 형태다.
- F절 18번(VLADriveBench, 추론이 장식)과 바로 연결된다. E2E 모델(문구 없음)의 해설은 구조상 행동에 영향을 줄 수 없다.

## 3. 회피 실험용 추가 옵션

r46 기준(`server/code/course/launch_r46.sh`):

```
--dataset data/course/lerobot/v46r
--base-checkpoint runs/navvla_reasoning_r26/checkpoints/last/pretrained_model
--steps 8000 --ce-weight 0.2
--obstacle-boost 4.0 --boost-target sampler
--contrast-twin-boost --contrast-twin-variants v0,v2
--sample-decode
```

| 옵션 | 뜻 | 도입 이유 |
|---|---|---|
| `--obstacle-boost 4.0` | 해설에 장애물이 나오는 프레임을 4배 자주 뽑음 | r5 교훈: 자연 빈도(프레임 10 %)로는 장애물을 완전히 무시함 |
| `--contrast-twin-boost` | 회피(v1)와 같은 출발·같은 프레임 위치의 직진 짝에 같은 가중치 | r36: 장애물 프레임만 4배로 뽑으면 "그 자리"만으로 꺾기를 예측할 수 있음 → 자리 지름길 |
| `--contrast-twin-variants v0,v2` | 빈 차선(v0)과 옆 차선 직진(v2) 짝 모두에 적용 | 10-02: 짝 시연 코퍼스(packed_boxpair)의 반례를 회피와 같은 비율로 뽑기 위함 |
| `--sample-decode` | 저장할 때마다 해설 2개를 생성해 로그에 남김 | 추론 헤드 상태 확인용 (느림) |

다른 실험에 쓴 옵션:

| 옵션 | 뜻 | 도입 |
|---|---|---|
| `--state-dropout` | 정규화된 상태(조향, 요 각속도)를 확률적으로 평균값으로 지움 | r37: 회피 중간 프레임 2782개 중 2579개가 조향·요 각속도만으로 풀림. 이미지를 볼 필요가 없어짐. F절 13번(자차 상태 지름길)과 같은 문제 |
| `--situation-prompt` | 정답 상황 문구를 지시문에 붙여 학습 | r40, r41: 인지 분리형 |

학습 로그에서 확인할 줄:
- `contrast twin boost: … (N twin/v1 pairs)`: 짝 수 (r45 60, r46 137)
- `sampled share by variant`: 가중 후 표본 비율 (r46: v0 14.7 % / v1 45.3 % / v2 40.0 %)
- `obstacle boost x4.0: …`: 가중된 프레임 수
- `trainable params: …M`: 실제 학습 파라미터 수 (서버 접속 불가로 이 문서에는 미기재)

## 5. 시사점과 다음 실험 후보

- **비전 고정 가설**
  - 비전 인코더는 1단계에서 장애물이 거의 없는 주행 장면에만 적응했다.
  - 장애물을 가르치는 2단계에서는 고정이다.
  - SmolVLA의 이미지당 64토큰 압축과 겹쳐서, 멀리 있는 박스 신호가 행동까지 약하게 전달될 수 있다.
  - r46 장애물 반응이 +0.27 m에 머무는 것과 맞는다. 미검증 가설이다.
- **검증 방법 두 가지**
  1. **이미지 반사실(학습 없음)**: 박스를 지우거나 붙인 프레임에서 행동 출력이 달라지는지 본다.
  2. **비전 풀기 비교**: r46 데이터와 설정을 그대로 두고 `freeze_vision_encoder=False`만 바꿔 학습한 뒤, 같은 20곳에서 평가한다.
     - 1단계가 이미 풀린 설정으로 3090에서 돌았으므로 메모리 문제는 없다(배치 8).
     - 비전에는 별도의 낮은 학습률을 두는 것이 안전하다.
- 반응이 크게 오르면 "VLA는 사전학습된 눈을 빌려 쓰지만, 새 물체를 보려면 눈도 같이 학습해야 한다"는 강좌 실습 포인트가 된다.

## 6. 시각 토큰 압축 — 얼마나 줄어드나, 어떻게 풀까 (2026-10-03 추가)

### 6-1. 64토큰이 만들어지는 과정

백본은 SmolVLM2-500M이다. Hugging Face 설정 기준으로 비전 hidden 768, 언어 모델 hidden 960, 이미지 512, 조각 16 px, 픽셀 셔플 배율 4다.

1. 512×512 이미지를 16×16 px 조각으로 자르면 32×32 = **1024조각**이다. SigLIP이 조각마다 768차원 특징을 뽑는다.
2. **픽셀 셔플**: 이웃한 4×4 = 16조각을 한 토큰으로 묶는다. 1024 ÷ 16 = **64토큰**, 토큰당 768×16 = 12,288차원이다.
3. **투영**: 선형층으로 12,288 → 960차원으로 줄여 언어 모델에 넣는다.
4. 결과적으로 토큰 하나가 원본의 **64×64 px 영역**을 대표한다. 화면을 가로 8 × 세로 8 바둑판으로 나눈 셈이다.
   - 우리 카메라는 640×480이다. 비율을 유지해 512×384로 줄이고 위아래를 빈칸으로 채운다. 그래서 실제 영상이 들어가는 칸은 **8×6 = 48칸**이다.

### 6-2. 몇 % 줄어드나

| 단계 | 숫자 개수 | 원본 대비 |
|---|---|---|
| ① 카메라 원본 640×480×3 | 921,600 | 100 % |
| ② 512로 축소 (실제 영상 512×384×3) | 589,824 | 64 % (36 % 감소) |
| ③ SigLIP 특징 1024 × 768 | 786,432 | 85 % (빈칸 포함) |
| ④ 픽셀 셔플 64 × 12,288 | 786,432 | 85 %, **줄지 않음** (묶기만 함) |
| ⑤ 투영 64 × 960 | **61,440** | **6.7 % (93 % 감소)** |
| ⑤ 중 실제 영상 48토큰 | 46,080 | **5 % (95 % 감소)** |

- 숫자 양으로는 원본의 약 **5 %**가 남는다. 실제로 줄이는 단계는 픽셀 셔플이 아니라 **투영**이다(토큰당 12,288 → 960, 92 % 감소).
- 위치 단위로는 픽셀 위치 307,200개가 **48칸**이 된다(**99.98 % 감소**). 칸 안의 세부 위치는 960개 숫자 속에 섞여서만 남는다.
- 주의할 점:
  - ①②는 색 값이고 ③ 이후는 학습된 특징이라, 숫자 개수 비교는 대략적인 감으로만 본다. 5 %가 남았다고 정보가 5 %만 남은 것은 아니다.
  - 다만 **작고 먼 물체의 세부**가 가장 먼저 희생된다.

### 6-3. 우리 박스에 적용하면

박스 폭은 1.6 m(`ob_box`)다. 차량 모델에 전방 카메라가 두 개(화각 62°, 100°) 있다. VLA 입력이 어느 쪽인지 **확인이 필요해서** 둘 다 계산했다(화면 폭 512 px, 핀홀 근사).

| 거리 | 화면 속 폭 (62°) | (100°) | 한 칸(64×64) 대비 면적 (62°) |
|---|---|---|---|
| 30 m | 약 23 px | 약 11 px | 약 13 % |
| 20 m | 약 34 px | 약 17 px | 약 28 % |
| 10 m | 약 68 px | 약 34 px | 약 1칸 |

- 시연은 박스 10 m 앞에서 꺾기 시작한다. 판단은 그보다 앞, 즉 **15~25 m에서 해야** 한다.
- 그 거리에서 박스는 **한 칸의 1/4 정도**다. 나머지는 도로, 차선, 배경과 섞인다.
- 비전 인코더가 2단계에서 고정이라(2절), 이 작은 차이를 키우도록 눈이 학습되지 않는다.

### 6-4. 해결 방법 — 싼 것부터

| 순서 | 방법 | 내용 | 비용 | 기대 |
|---|---|---|---|---|
| 0 | **진단: 이미지 반사실** | 박스를 지우거나 붙인 프레임에서 행동 출력 차이를 본다. 거리별로(10/20/30 m) 보면 **어디부터 안 보이는지**가 나온다 | 학습 없음, 수십 분 | 원인 확정. 아래 방법의 선택 근거 |
| 1 | **비전 인코더 풀기** | 2단계에서 `freeze_vision_encoder=False`, 비전은 낮은 학습률(예: 1e-6~5e-6) | r46 재학습 1회(약 1 h) | 눈이 "칸 안의 작은 박스"를 드러내도록 적응. 추론 CE("앞 장애물")가 눈까지 기울기를 보냄 |
| 2 | **확대 영상을 빈 카메라 칸에 넣기** | 지금 카메라 3칸 중 2칸은 빈 이미지다(`empty_cameras=2`). 한 칸에 **전방 도로 중앙을 잘라 2배 확대한 영상**을 넣는다 | 데이터 재변환 + 브리지·서버 입력 수정. **연산은 그대로**(빈 이미지도 이미 인코더를 통과함) | 20 m 박스가 약 68 px = 1칸 이상. 먼 물체 해상도 2배. 학습된 3카메라 구조를 그대로 씀 |
| 3 | **좁은 화각 카메라 사용** | 100° 카메라라면 62° 카메라로 바꾼다 | 수집 재실행 | 같은 거리에서 박스 크기 약 2배. 대신 차선 시야가 좁아짐 |
| 4 | **먼 장애물 프레임 가중** | `--obstacle-boost`를 거리별로 준다. 15~30 m 프레임을 더 뽑는다 | 옵션 추가, 재학습 | 판단 시점의 작은 박스 예제를 더 많이 봄. 단, 눈이 고정이면 효과 제한 |
| 5 | **장애물 보조 손실** | 시각 토큰 위에 "박스 있음/칸 위치" 분류 헤드를 붙여 함께 학습한다(1과 함께) | 코드 추가 | 눈이 박스를 직접 표시하도록 강제 |
| 6 | 토큰 수 늘리기 | 픽셀 셔플 배율 4 → 2(256토큰), 또는 SmolVLM 타일 분할 | 투영층 재학습, 사전학습 가중치와 불일치, 연산 4배 | 근본 해결이지만 2주 일정에는 무거움 |
| 7 | 인지 분리 | 검출기(YOLO)나 VLM이 박스를 찾아 문구로 넘긴다 | 이미 있음(r41) | 토큰 압축을 우회. E2E 비교 실습의 대조군 |

추천 순서는 이렇다.
- **0 → 1 → 2**: 0으로 "몇 m부터 안 보이는지" 확인하고, 1로 눈 적응 효과를 본다.
- 1로 부족하면 2(확대 영상)를 넣는다. 2는 SmolVLA의 다중 카메라 구조를 그대로 쓰고 연산이 늘지 않아서 가장 가성비가 좋다.

- VLA 입력 카메라가 62°와 100° 중 어느 쪽인지 브리지 토픽 설정으로 확인한다.
- 2번을 쓰려면 실제 트랙 카메라에서도 같은 크롭이 가능한지 본다. 해상도가 충분해야 한다.
