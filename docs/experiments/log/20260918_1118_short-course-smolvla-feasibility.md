# Physical AI 단기강좌 — SmolVLA 실차 실습 실현 계획 (2026-09-18)

강좌 구성안(`Physical_AI_Course_Plan_0917.pdf`, 오프라인 3일 10~18시, 3일차 17시
산업체 특강)을 현재 자산(nav-vla, VLA_AD, 선배 VLA_Simulation)에 대조해
"실제로 되는가"를 판정하고, 되게 만드는 준비 순서를 정한 문서.

## 0. 한 줄 결론

**시간표는 성립한다.** 단, ① 학습은 "조교 베이스 체크포인트에서 팀 데이터로
짧게 resume", ② 출발·정지·속도·장애물 판단은 프로그램, ③ VLA는 "차선 조건부
조향"만 배운다는 세 가지 설계 위에서, 그리고 **강좌 전에 SmolVLA 실차 폐루프를
한 번 돌려 본 뒤**에만 성립한다. 준비 기간 2~3주.

## 1. 확정된 설계

| 요소 | 결정 | 근거 |
|---|---|---|
| VLA 입력 | 이미지 + 상태 [steer, speed] + 명령 문장 | 라이다 없음 |
| 명령 문장 | 4개 고정: 1차선 유지 / 2차선 유지 / 2차선으로 변경 / 1차선으로 변경 | 출발·정지·속도는 학습 대상에서 제외 |
| VLA 출력 중 사용 | **조향만**. 속도는 프로그램 값으로 대체 | v6 데모의 서빙 speed-shaping 전례 |
| 출발/정지/속도 증감 | 대시보드 버튼 → 프로그램 | VLA_AD 대시보드에 estop·speed_override·lane 강제 이미 있음 |
| 차선변경 판단 | 프로그램이 명령 문장 전환 | |
| 장애물 인지 (3일차) | Qwen-VL 제로샷 "전방 같은 차선에 차량?" → 차선변경 명령. 학습 0 | 선배 `vla_brain_node`·VLA_AD `vla_trt`와 같은 구조. YOLO는 VLA 강좌 취지와 어긋나 배제 |
| 학습 방식 | 조교 베이스에서 팀 데이터로 resume 5K~10K steps | 처음부터 학습은 첫 시도 실패 확률 높음 (시뮬 v2 이력) |
| 학습 장소 | 팀별(8팀) Colab 계정. 대안: 서버 3090 + 4070Ti 순차 | T4 처리량 실측 후 확정 |
| 실차 스택 | VLA_AD (Thor, Jazzy) 위에 SmolVLA 정책 노드가 `motion_planner` 자리를 대체 | |

## 2. 학습 시간 — 이미지 수가 아니라 스텝 수

기록된 실측(3090, batch 8, AMP):

| 런 | 프레임 | steps | 소요 | 출처 |
|---|---|---|---|---|
| v3y (7월) | 39.6k | 40K | 5.2h (2.15 step/s) | ver/20260731_1731 |
| v6~v8 (8월) | 93.7k | 60K | 8.6h (1.9 step/s) | vla_complete_guide_ko §6 |
| r1~r24 (9월) | 39.6k~66.5k | 25K | 2.6~2.7h (0.38 s/step) | reasoning_versions §3 |

같은 4만 장이 40K면 5.2h, 25K면 2.7h. 즉 **스텝을 정하면 시간이 정해진다.**
3~4h 예산이면 25K~30K, resume 10K면 1.1h, 5K면 0.55h.

Colab 무료 T4 추정: bf16 미지원·연산 3~5배 느림·vCPU 2개(비디오 디코딩
병목) → 10K에 4~5h. **실측 전에는 팀 학습 장소를 Colab으로 확정하지 않는다.**

## 3. 이미지가 많이 필요한가 — 단위는 "궤적 × 상태 커버리지"

YOLO 세그멘테이션 3천 장과 다른 이유:

- 라벨 밀도: 세그는 한 장에 수만 픽셀 감독, VLA는 한 장에 액션 청크 하나.
- 프레임 상관: 10Hz 연속 프레임은 옆 프레임과 거의 같다. v3y 39.6k 프레임의
  실제 다양성은 173 궤적.
- 폐루프 복합 오차: 모델이 만든 오차가 다음 장면을 바꾼다. **차선 중앙에서
  벗어난 상태의 복귀 데이터**가 없으면 장수를 늘려도 못 돌아온다 (구세대
  619ep 코퍼스가 정확히 이 문제, 복구 데이터 0).

강좌 범위(한 트랙, 차선 유지 + 변경)의 수집 지침:

- 차선 2개 × 3~5바퀴
- 차선변경 양방향 각 10회
- **일부러 치우쳤다 복귀하는 주행 2바퀴** (필수)
- → 15~20분, 10Hz 약 1만 프레임, 30~50 궤적. 수집 시간은 병목이 아니다.

이 규모로 몇 스텝이 필요한지는 **실측이 없다**(173ep·25K 미만 기록 없음).
§6 실험 2로 확정한다. 선배 리포처럼 pose+중심선 재라벨을 넣으면 최소치가
더 내려간다.

## 4. 선배 VLA_Simulation과의 차이

| | VLA_Simulation | nav-vla + SmolVLA |
|---|---|---|
| 모델 | Qwen3-VL 비전 **동결** + 작은 헤드 → 6 웨이포인트 → pure-pursuit | SmolVLA 전체(언어·상태가 액션 익스퍼트에 cross-attn) |
| 언어 조건 | FiLM 차선 ID 하나. 자연어는 별도 Qwen 브레인이 표준 명령으로 변환 | 문장이 직접 정책에 들어감 |
| 라벨 | pose + 트랙 중심선 GT로 자동 생성, 텔레포트 복구·DAgger 합성 | 기록된 조작값 |
| 학습 | 특징 1회 캐시 후 9초/에폭, ~15분 | 25K 2.7h |

엄밀히 선배 Fast path는 "이미지→웨이포인트 회귀기"이지 언어 조건부 VLA가
아니다. 15분 학습은 그 대가다. 같은 캐시 트릭은 SmolVLA에 적용 안 된다.
Colab 사용도 학습이 아니라 사전학습 헤드 **추론 시각화**뿐이다.

가져올 것: ① pose 기반 재라벨(복귀 데이터 균일화), ② 합성 차선변경 데이터,
③ "사전학습 모델 + Colab 추론 노트북" 패턴(온라인 과제용).

## 5. VLA_AD가 이미 해결한 것

[VLA_AD](https://github.com/sunhong7867/VLA_AD) (Thor, Jazzy, 카메라 only):

| 필요 항목 | 현황 |
|---|---|
| 제어 계약 | `MotionCommand(steering -7~7, left/right speed)` → `serial_sender` → Arduino `s{}l{}r{}` |
| 수동주행 레코더 | `src/data_collection/data_collection.py`: 키보드, 10fps, 640×480, **mp4 + CSV[ts, steering, left_speed, right_speed, lane]**, 차선 태그 키 |
| 실차 폐루프 | YOLO 차선 + 플래너로 5분 trial 다수 (P4). VLM은 0.74Hz로 속도 배율·차선 지정만 |
| VLM 추론 | Qwen3-VL-8B INT4 TRT 엔진 (`vla_trt`) 상주 |
| Thor 위 SmolVLA | nav-vla `docs/guides/thor_smolvla_demo.md` — lerobot 0.4.4 설치·시뮬 데모 실행 이력. **추론 Hz 미기록** |

즉 "학습된 정책이 조향을 만든 실차 주행"만 없다. 레코더 CSV는 SmolVLA
입력(이미지 + 상태 + 차선 문장 → 조향)에 그대로 대응한다.

## 6. 강좌 전 준비 (2~3주)

| 순서 | 작업 | 산출물 | 예상 |
|---|---|---|---|
| 1 | **CSV→LeRobot 변환기**: `record_*_labels.csv` + mp4 → state [steer, speed], action [steer, speed], lane 태그 → 4문장 task | `convert_vlaad_to_lerobot.py` | 반나절 |
| 2 | **Thor SmolVLA 정책 노드 + 액션 어댑터**: nav-vla `vla_policy_server` 재사용, steer 연속→정수 -7~7 양자화, 속도는 프로그램 값, `motion/command` 발행 → 기존 `serial_sender`. `motion_planner` 대체 | 노드 1개, Thor 추론 Hz 실측 | 1~2일 |
| 3 | **조교 베이스**: 레코더로 차선 유지·변경·복귀 30~50 궤적 → 3090 25K → **실차 한 바퀴** | 베이스 체크포인트 = 2일차 백업 모델 | 2~3일 (재학습 1회 포함) |
| 4 | 실험 1: **Colab T4 처리량** — 3의 데이터 20 ep로 300 step, step/s·VRAM·fp16 안정성 | 팀 학습 장소 결정 | 30분 |
| 5 | 실험 2: **최소 데이터 스윕** — 3의 실차 데이터로 {20, 40 ep} × {3K, 5K, 10K} resume, 판정 "이탈 없이 한 바퀴" | 팀 학습 레시피 (N ep × S steps) | 밤샘 1~2회 |
| 6 | 장애물 VLM 판정: `vla_trt` 프롬프트에 "전방 차량 → 차선변경" 추가, 거리 임계 튜닝 | 3일차 데모 | 반나절 |
| 7 | 팀용 Colab 노트북 2개: (a) 베이스 로드 → 팀 데이터 → resume → 체크포인트 다운로드, (b) 추론 시각화 (온라인 과제) | | 1일 |
| 8 | **전체 리허설**: 조교가 학생 역할로 1일차 절차를 시간 재며 1회 | 매뉴얼 확정 | 1일 |

리허설 없이 강좌에 들어가지 않는다. 시뮬에서도 첫 모델은 항상 실패했다.
