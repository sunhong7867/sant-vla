# 최근 연구 정리 · 2026-09-18

> Notion 반영 완료: https://app.notion.com/p/3dfe2f9cc589818d80faf572e4448782 — 메인·기능별 검증 현황·문제와 다음 실험도 갱신했다. 09-15~09-18 로컬 연구 기록과 현재 데모 스크립트를 기준으로 정리했다. 서버 활성 모델이나 새 주행은 이번 정리에서 확인하지 않았다. 관련 코드와 새 일지는 로컬 미커밋 변경을 포함한다.

## 핵심 요약

- **로컬 데모 기본 구성:** r26 + 빠름 티어 횡오차 보정(`XTRACK_GAIN=0.15`, `XTRACK_TIERS=fast`). `smolvla_demo.sh`에서 확인했다.
- **성과:** Stanley 선생 기반 r26은 2차선·보통 평가에서 기준 초과 비율 0%를 기록했다. 횡오차 보정은 빠름 티어 결과를 개선했다.
- **남은 한계:** 전 차선·속도 조건에서 반복 무접촉을 달성한 것은 아니다. r26 + 보정의 표에는 6~13% 수준의 기준 초과가 남아 있다.
- **강좌 방향:** SmolVLA는 차선 조건부 조향을 담당하고, 출발·정지·속도 및 차선변경 판단은 프로그램이 담당하는 실차 실습을 준비한다. 실차 폐루프 성공과 학습 처리량 실측이 선행 조건이다.

### 선생 제어기의 위상 진단

| 지표 | YOLO(v3y) | Pure Pursuit(v10) |
|---|---:|---:|
| 경로 곡률 대비 조향 lag | +2.12 프레임 | −1.20 프레임 |
| 조향 변화량 평균 | 0.0085 | 0.0051 |
| 경로 곡률 구간 내 조향 표준편차 | 0.032 | 0.019 |

Stanley 본수집에서는 lag −0.11, 중앙 오프셋 0.109m, 최대 0.264m, 밟음 0%가 기록됐다. 이후 r26의 보통 조건 개선은 선생의 위상 특성이 모방 안정성과 관련 있다는 가설을 지지한다.

**해석 범위:** 제어기 교체는 위상 외에도 오프셋·행동 분포를 함께 바꾼다. 따라서 ‘위상이 유일한 원인으로 확정’, ‘복원 데이터가 일반적으로 무효’라는 결론은 아직 분리 실험이 필요하다. 과거 일지의 강한 표현은 당시 해석으로 보존한다.

## 2. 횡오차 보정과 모델·코드 역할

Gazebo 포즈와 명령 차선 중심선으로 횡오차를 계산해 실행 곡률을 보정한다. 기록된 설정은 gain 0.15, cap 0.06, deadband 0.15m이며 빠름 티어에 적용한다.

| 조건 | r26 단독 | r26 + 보정 |
|---|---:|---:|
| 2차선·보통 | 0% | 6% |
| 1차선·보통 | 8.6% | 8~13% |
| 2차선·빠름 | 32~44% | 8.3% |
| 1차선·빠름 | 38~44% | 9.6% |

1차선·빠름 단일 실행에서 gain 0.15/0.20 설정의 0% 기록도 있으나, 전체 조건의 반복 무접촉을 증명하지 않는다. 보통 조건은 빠름 전용 보정의 직접 적용 대상이 아니므로 표의 차이를 보정 효과로 단정하지 않는다.

이 결과는 **좌표 피드백을 포함한 시스템 성능**이다. 모델 단독 성능과 구분하고, 실차에서는 동일한 위치·중심선 정보를 어떻게 얻을지 별도 검증해야 한다.

## 3. 대시보드와 감독 기능

- **속도 트렌드:** `/cmd_vel`의 최근·과거 평균 차이로 ‘올림/줄임/유지’ 표시를 보정한다. 이는 명령속도 기반 표시이며 실제 차량 속도의 센서 측정값이나 모델 설명 정확도 향상을 뜻하지 않는다. 인과적 설명 꼬리는 유지한다.
- **바퀴 수:** 출발 차선의 누적 호길이를 이용해 바퀴를 세고, 지정 횟수에 도달하면 감독 코드가 정지한다. `/vla/lap`으로 진행률을 전달한다.
- **남은 검증:** 실제 데모에서 트렌드 표시, 루프 경계 통과, 투영 지터, 목표 바퀴 정지의 반복 확인. 이번 정리에서는 추가 주행하지 않았다.

## 4. Physical AI 단기강좌 준비안

09-18 계획을 최신 준비안으로 사용한다. 기존 발표 Q&A의 ‘사전학습 모델 운용 중심’ 설명과 구분하고, 학생이 팀 데이터로 짧게 추가 학습하는 흐름을 반영한다.

| 항목 | 준비안 |
|---|---|
| 입력 | 이미지 + 상태 [steer, speed] + 4개 고정 차선 문장 |
| 모델 담당 | 차선 유지·변경을 위한 조향 출력 |
| 프로그램 담당 | 출발·정지·속도, 차선변경 명령 전환 |
| 장애물 확장 | Qwen-VL 판단 → 프로그램 명령 → VLA 조향. 구현·실차 검증 전 계획 |
| 학습 | 조교 베이스에서 팀 데이터로 5K~10K step resume |
| 데이터 수집 목표 | 15~20분, 약 1만 프레임·30~50 궤적. 복귀 주행 포함; 최소 필요량 실측 전 |
| 운영 | 1일차 수집·학습 → 2일차 주행 → 3일차 장애물 확장 |

### 준비 순서와 완료 기준

1. CSV·영상→LeRobot 변환기: 상태·행동·차선 문장과 시간 정렬 확인.
2. Thor 정책 노드·어댑터: 조향 -7~7 변환, 프로그램 속도, 추론 Hz 실측.
3. 조교 베이스: 실차 데이터 학습 후 실차 폐루프 한 바퀴 검증.
4. Colab T4: 20ep·300step 시험으로 처리량·VRAM·fp16 안정성 측정 후 학습 장소 결정.
5. 최소 레시피: {20, 40ep} × {3K, 5K, 10K} 비교, ‘이탈 없이 한 바퀴’ 판정.
6. 장애물 명령 연동, 팀용 노트북, 전체 시간표 리허설.

준비 기간 2~3주와 학습 시간은 계획치다. T4 처리량, Thor 추론 Hz, 실차 최소 데이터량은 미확정이다. 3090의 기록상 약 0.38s/step에서 5K는 약 0.53시간, 10K는 약 1.06시간이며 Colab에 그대로 적용하지 않는다. 실차 준비가 미달하면 Gazebo 실습으로 전환하고, 팀 모델 실패 시 조교 베이스를 사용한다.

## 5. 다음 연구 과제

- 같은 checkpoint·서빙 설정·시작 조건에서 모델 단독과 횡오차 보정 구성을 비교한다.
- 차선×속도×방향별 반복 수, 주행 시간·거리, 기준 초과 표본/전체 표본, 이탈, 개입 로그를 남긴다. 미정인 반복 수·통과 기준은 실행 전에 확정한다.
- 위상 가설은 다른 조건을 통제한 비교로 추가 검증한다. r27 실패를 근거로 데이터량·분포·학습 스텝의 효과를 한꺼번에 배제하지 않는다.
- 모델 원문 설명과 대시보드 보정 문장을 각각 보관한다. 설명의 인과적 충실성은 여전히 별도 검증 대상이다.
- 강좌용 실차 검증과 시뮬레이션 연구 결과를 분리해 기록한다.
