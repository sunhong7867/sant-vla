# `EGO_HALF_LEN` 실측 — gap 지표가 0.396 m 틀렸다, "지나쳤다"는 "닿기 직전에 섰다"였다 (2026-10-12 17:55)

10-08 미해결 2번(*"`EGO_HALF_LEN=2.3` 이 근거가 약한 상수 — `avoidance_trial.py` 는 2.4, SDF 의
front_bumper 앞면은 1.904 로 보고됨, 미확인"*)을 SDF 에서 직접 재어 닫는다.

## 1. 실측

`src/simulation_pkg/models/prius_hybrid/model.sdf` 의 모든 충돌 기하를 링크 pose + 요소 pose +
박스 반폭으로 합산했다. **전방은 모델 로컬 −y** 다(SDF 주석: *"the model's nose is at y = −2.24"*).

| 충돌 요소 | 앞끝 y | 뒤끝 y |
|---|---|---|
| `front_bumper` | **−1.904** | −1.496 |
| `hood` | −1.825 | −1.406 |
| 앞바퀴 (좌/우) | −1.464 | −0.933 |
| `windshield` | −1.447 | −0.041 |
| `chassis` | −0.850 | +0.935 |

| 값 | |
|---|---|
| **충돌 기하 앞끝** | **원점 → 1.904 m** |
| 충돌 기하 뒤끝 | 원점 → 1.964 m (`back_bumper`) |
| 전장 (충돌) | **3.868 m** — 처음 4.563 m 로 적었는데 그건 차체 밖에 떠 있던 `lidar_collision`(y +2.659)을 포함한 값이었다. 라이다를 앞범퍼로 옮긴 뒤 차체만 남은 값이다 |
| 시각 메시 코끝 | 2.24 m (SDF 주석) |

즉 **세 값이 서로 다른 것을 재고 있었다**: 1.904 = 충돌 앞끝(물리적 접촉), 2.24 = 시각 코끝,
2.3 = 코끝에 가까운 어림값. `avoidance_trial.py` 의 2.4 는 근거를 찾지 못했다.

## 2. 지표 교정 — 부호가 바뀐다

`gap = 중심거리 − EGO_HALF_LEN − r` 로 계산해 왔다. `EGO_HALF_LEN` 이 0.396 m 과대였으므로
**기록된 gap 은 모두 그만큼 과소**다.

| 측정 | 기록된 gap | 교정 후 |
|---|---|---|
| s1/s0/r26 (10-08, n=150) 중앙 | −0.39 m | **+0.006 m** |
| s3 (10-09, 맞은 물체 정차 n=1) | −0.18 m | **+0.216 m** |
| g4 문서 기록 | −0.37 m | **+0.026 m** |

**해석이 바뀐다.** "늘 지나치거나 닿는다"가 아니라 **"닿기 직전에 섰다"** 다. 차는 감속해서
멈추고 있었고, 멈춘 자리가 시연보다 약 1.6 m 가까웠을 뿐이다.

그 1.6 m 도 설명된다. 교사의 실제 여유는 `2.300 + 1.2 − 1.904 = **1.596 m**` 다(의도한
`STOP_GAP` 1.2 m 이 아니다 — 상수 오차가 교사를 그만큼 보수적으로 만들었다). 10-08 문서의
*"최근접 거리가 교사 standoff 보다 약 1.6 m 짧은 좁은 군집"* 과 자리 수가 맞는다.

## 3. 바뀌는 것 / 바뀌지 않는 것

**바뀌지 않는다**: STRICT 0/180 은 그대로다. STRICT 는 "시연 standoff 에서 정차"이고 교정은
0.4 m 짜리라 1.6 m 부족을 메우지 못한다. `COLLISION` 판정도 중심거리 2 m 가드라 무관하다.

**바뀐다**: 고장의 성격이다. "정차 행동이 없다"가 아니라 **"정차 거리가 1.6 m 틀렸다"** 다.
전자는 종단 데이터 공백(standoff 이내 0/50,706)으로만 설명되지만, 후자는 그 공백의 **직접적
귀결**이다 — 시연에 중심거리 3.95 m 안쪽 프레임이 하나도 없으니 "여기서 서라"는 신호가 없고,
정책은 자기가 아는 마지막 상태까지 가서 멈춘다.

## 4. 적용 — 상수를 둘로 쪼갰다 (사용자 지시)

하나가 두 일을 하고 있었다. 쪼개서 쓰임마다 맞는 값을 쓴다.

| 쓰임 | 상수 | 값 |
|---|---|---|
| 교사 정차 거리 `standoff()` | `EGO_HALF_LEN` | **2.3 유지** — 바꾸면 신규 수집이 10-12 이전 코퍼스와 비교 불가 |
| 평가 지표 `gap`·`touched` | **`EGO_COLLIDE_LEN`** | **1.904** (충돌 앞면) |

| 파일 | 변경 |
|---|---|
| `goto_layout.py` | `EGO_COLLIDE_LEN = 1.904` 추가, 두 상수의 쓰임을 주석으로 분리 |
| `tools/eval/goto_trial.py` | `gap`·`touched` → `EGO_COLLIDE_LEN` |
| `driving_dashboard.py` | GUI 의 `gap` 표시 → `EGO_COLLIDE_LEN` |

`standoff(go_cone_red)` = 3.950 m 불변을 확인했고, 그 자리의 실제 여유는 1.596 m 다.
STRICT 창 `0.6 ≤ gap ≤ 1.8` 안에 들어가므로 판정 기준은 그대로 쓸 수 있다. 다만
**창이 시연값 1.596 m 에 대해 비대칭**이다(아래로 1.0 m, 위로 0.2 m). 런 간 기준을
동일하게 유지하려고 손대지 않았다 — 재중심화는 별도 결정이다.

`tools/eval/avoidance_trial.py` 의 `EGO_HALF_LEN, EGO_HALF_WID = 2.4, 0.95` 는 **건드리지
않았다.** 충돌 발자국 판정이므로 1.904 가 맞지만, a1 사전등록의 기각선(`adj` 충돌 ≤ 2/20)이
그 값으로 쓰여 있고 수집이 진행 중이다. 실험 중간에 판정 기준을 바꾸지 않는다.

## 5. 2D 라이다 — 옮겼고, 그 과정에서 **트리거가 죽어 있었다**는 걸 찾았다

실습용 2D 라이다 활용을 검토하는 중이라 위치를 재다가 발견했다.

`smolvla_demo.sh` 는 이 센서를 **"회피 주 트리거"** 로 띄운다. 그런데
`eval_out/demo/lidar_obstacle.log`(10-10 데모) **835 줄 전부** 이렇다.

```
[argmin] nearest beam overall: idx=267 (~267deg) 0.70m  | front 0-15deg nearest=inf detected=False
```

| | |
|---|---|
| `detected=True` | **0 회** |
| `detected=False` | 835 회 |
| `front 0-15deg nearest=inf` | **835 회 (전부)** |

**고장이 두 개 겹쳐 있었다.**

**(1) 마운트** — `lidar_link` 가 원점 기준 y = **+2.609**, 즉 뒷범퍼 앞면(+1.964)보다
0.645 m 더 뒤, **차체 밖에 떠 있었다**(코끝까지 4.51 m). 전방 레이가 자기 차체에 막혔다 —
argmin 이 늘 idx 265~273 에서 **0.70 m** 를 찍는데, 그게 자기 뒷범퍼(0.645 m + 센서 반경)다.

**(2) 섹터** — 설정된 `start_angle 0 / end_angle 15` 는 전방이 아니다. 센서 프레임 0° 는
+x(우측)이고 **차량 전방은 로컬 −y = 270°** 다. 위 argmin 중심 269° 와 일치하고, 노드
docstring 의 경고(*"The body has a ~90 deg yaw offset, so the real forward sector may not
be 0-30 deg — find it via /scan argmin when an obstacle is dead ahead"*)가 바로 이것이다.
섹터가 옆을 보고 있었으니 12 m 안에 아무것도 없어 `inf` 였다.

### 적용

| 대상 | 변경 |
|---|---|
| `prius_hybrid/model.sdf` `lidar_link` | `8e-06 2.60856 0.829644` → **`0 -1.80 0.70`** |
| `smolvla_demo.sh` 검출 노드 | `-p start_angle:=262 -p end_angle:=278` 추가 (전방 ±8°) |

좌표 선택 근거: **y = −1.80** 이면 충돌 실린더(r 0.0508)가 −1.851~−1.749 로 앞범퍼 앞면
−1.904 **안쪽**에 머물러 `EGO_COLLIDE_LEN = 1.904` 가 불변이다. **z = 0.70** 이면 앞범퍼
위끝 0.631 을 넘어 전방 레이가 가려지지 않고, `go_cone_*`(실린더 r 0.45 × 높이 **1.3 m**)와
차량 모두 맞는다. yaw 는 0 그대로라 인덱스-각도 매핑이 바뀌지 않는다.

적용 후 재검증: 충돌 앞끝 1.904 불변, 뒤끝 1.964(`back_bumper`), 차체 전장 3.868 m.
`nav-vla` → `sant-vla` 심링크 + colcon symlink-install + `.egg-link` 라 **재빌드 없이
시뮬·평가에 즉시 반영**된다(inode 동일 확인).

### 주의 — 회피 발화 시점이 바뀐다

`range_max:=8.0` 의 의미가 달라진다.

| | 전 | 후 |
|---|---|---|
| 센서 → 코끝 | −4.51 m (뒤) | +0.10 m |
| `range_max 8.0` 의 실질 | 코끝 앞 **3.49 m** | 코끝 앞 **7.90 m** |
| 실제 동작 | 자기 차체에 막혀 **발화 0** | 발화함 |

주석의 설계 의도(*"2 m/s 기준 차선 변경(~4 s)에 필요한 여유"*)와 **처음으로 일치**한다.
그러나 **avoidance 결과는 이 날짜 전후로 비교하지 않는다.** 과거 회피 성공(감독 4/6 등)은
이 트리거가 죽은 상태에서 나온 것이므로, 실제로는 **VLM 목격 경로가 단독으로 낸 결과**다.
a1 수집은 ground-truth `_ob_arc_gap` 으로 유발하므로 영향받지 않는다.
