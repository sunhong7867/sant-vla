## 1. 질문과 동기

**질문:** 학습이 끝난 SmolVLA 주행 모델(v3y)을 INT8/INT4 로 양자화(PTQ)하면
(a) 추론 지연시간과 GPU 메모리가 얼마나 줄고,
(b) 차선 유지 품질과 지시 문장에 대한 반응이 얼마나 나빠지나?

**동기:** 지금 데모 정책 서빙은 노트북이 아니라 랩서버 4070 Ti 에서 돈다.
`smolvla_demo.sh:221` 주석(2026-08-28 결정): 노트북 GPU 4.7 GB·RAM 3 GB 를 아끼고,
추론 106 ms 로 로컬 대비 2.5배 빠르며, ssh 터널 왕복은 114 ms.
양자화로 노트북 로컬 추론이 이 왕복 시간보다 빠르고 시뮬과 메모리를 같이 쓸 수 있게 되면,
**랩서버 없이 노트북 하나로 데모·강좌를 돌릴 근거**가 된다. Jetson 배포 준비와도 이어진다.

## 2. 고정 조건

| 항목 | 값 |
|---|---|
| 모델 | v3y (`models/server/navvla_smolvla_v3y/last/pretrained_model`) — 순수 주행 품질이 가장 좋은 모델(빈 트랙 차선중심 중앙값 0.25 m) |
| 모델 구조 | SmolVLM2-500M 백본 16층, action expert 폭 0.75, flow-matching `num_steps 10`, 청크 30 |
| 저장 형식 | BF16, `model.safetensors` 907 MB (약 450M 파라미터) |
| 입력 | 카메라 1장 + state 3차원 `[v, ω, δ]` + 지시 문장 |
| 출력 | 30 × `[dx, dy, dyaw]` (ego-frame 이동량, `docs/guides/io_contract_state_action_twist.md`) |
| 노이즈 | `infer1()` 이 `torch.manual_seed(seed)` 로 고정 (`server/code/vla_policy_server.py:216`) → 조건끼리 같은 노이즈로 비교 가능 |
| GPU | 1·2단계: 랩서버 RTX 3090 / 4070 Ti. 3단계: 노트북 RTX 4060 Laptop 8 GB |
| 도구 | `torchao` 의 `quantize_()` |

## 3. 비교 조건

| 이름 | 내용 | 기대 |
|---|---|---|
| **FP32** | 전체 32비트 | 정확도 기준(상한) |
| **BF16** | 현재 저장 형식 그대로 | 지연·메모리 기준 |
| **W8A16** | 모든 Linear 가중치 INT8, weight-only | 메모리 절반, 정확도 거의 유지 예상 |
| **W8A8** | INT8 동적 활성값 + INT8 가중치 | 배치 1 에서는 오히려 느릴 수 있음 → 측정으로 확인 |
| **W4A16** | INT4 weight-only, group 128 | 메모리 최소, 정확도 손실 가능성 가장 큼 |
| **W8A16-mixed** | 비전 인코더 + 언어모델만 INT8, action expert·출력 projection 은 BF16 | 정확도와 효율의 절충 |
| (대조군) **steps5** | BF16, `num_steps 10 → 5` | 양자화가 아닌 지연시간 레버. 효과 크기 비교용 |

각 조건을 `torch.compile` 끈 것/켠 것 두 번 측정한다. 정수 커널 이점은 compile 이 있어야 드러나는 경우가 많다.

## 4. 1단계: 오프라인 벤치 (랩서버)

같은 입력 프레임을 모든 조건에 넣고 출력을 비교한다. 시뮬은 쓰지 않는다.

### 4.1 입력 세트
- v3y 학습에 쓰지 않은 에피소드에서 프레임 N = 500
- 직선 / 커브 / 속도 지시 3단계(느리게·보통·빠르게)가 고르게 섞이도록 뽑는다
- 프레임 목록은 파일로 저장해 모든 조건이 같은 세트를 쓰게 한다

### 4.2 지표

| 지표 | 계산 | 왜 |
|---|---|---|
| **행동 오차** | 같은 seed 에서 조건 출력 − FP32 출력. `dyaw`(조향), `dx`(속도), 곡률 `dyaw/dx` 의 MAE. 청크 첫 10스텝(실제로 실행되는 구간)과 전체 30스텝을 따로 | 양자화가 행동을 얼마나 바꾸나 |
| **노이즈 바닥** | FP32 끼리 seed 만 바꿨을 때 위 차이 | 모델이 원래 갖는 출력 흔들림. 양자화 오차를 이것과의 비율로 판단한다 |
| **언어 민감도 보존** | 같은 프레임에 속도 지시만 바꿨을 때 출력 `dx` 차이. FP32 대비 몇 % 가 남는가 | 작은 언어 신호가 양자화 잡음에 묻히는지 |
| **지연시간** | 워밍업 후 청크 1개 추론 시간 중앙값·p95 (기존 서버 워밍업 측정 방식, `vla_policy_server.py:259-282`) | 효율 |
| **GPU 메모리** | `torch.cuda.max_memory_allocated()`, 로드 직후와 추론 중 | 노트북 공존 가능성 |
| **모델 크기** | 양자화 후 state_dict 크기 | 참고 |

### 4.3 통과 기준 (초안)
- 조향 MAE(첫 10스텝) ≤ 노이즈 바닥 × 1.5
- 언어 민감도 보존 ≥ 90 %
- 지연시간이 BF16 대비 20 % 이상 단축 **또는** GPU 메모리 40 % 이상 절감

통과한 조건 중 상위 2개만 2단계로 보낸다.

## 5. 2단계: 폐루프 주행 (시뮬)

오프라인 오차가 작아도 주행에서는 오차가 쌓인다. 실제로 돌려서 확인한다.

### 5.1 차선 유지
- 빈 트랙, 문장 `"Cruise in the outer lane, at a normal speed."`, 5랩
- r11/v3y 비교(2026-09-10)와 같은 프로토콜
- `tools/eval/geometric_lane_check.py` 로 기하 차선중심 대비 횡오차: 중앙값, p95, 최대, 접촉 여유 0.70 m 초과 비율
- **게이트:** 중앙값 ≤ 0.30 m, 그리고 같은 날 측정한 BF16 대비 +0.05 m 이내

### 5.2 속도 지시
- 느리게 / 보통 / 빠르게 각 1랩 → 실측 평균 속도
- 세 단계의 속도 차이가 BF16 과 같은 순서·비슷한 간격으로 유지되는지

### 5.3 실행 절차
- `sim-stack-bringup` 절차대로: 실행 중인 스택 확인 → 정리 → RAM 프리플라이트 → 기동
- 테스트용 `ROS_DOMAIN_ID` 분리 (라이브 데모와 섞이지 않게)
- 서빙은 기존 원격 경로를 쓴다: `server/start_demo_policy.sh` 에 양자화 인자만 추가
- 조건마다 BF16 기준을 같은 날 다시 돌린다 (날마다 스택 상태가 달라서)

## 6. 3단계: 노트북 로컬 서빙 (선택)

1·2단계에서 쓸 만한 조건이 나왔을 때만 한다.

- 노트북에 lerobot + torchao 가상환경을 새로 만든다 (현재 `.venv` 에는 lerobot 이 없음)
- `LOCAL_VLA=1 ./smolvla_demo.sh` 로 최선 조건을 서빙
- 확인할 것:
  - 로컬 추론 지연이 원격 왕복 114 ms 보다 짧은가
  - 시뮬(gz) + 정책 서버를 같이 띄워도 GPU 8 GB·RAM 이 버티는가 (데모 노트북 리소스 한계 참고)
  - 5.1 의 차선 유지 게이트를 노트북에서도 통과하는가

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| torchao 와 서버 torch 버전이 안 맞음 (서버 코드 주석: torch/transformers/av 버전 맞추기가 이미 까다로움) | 기존 venv 를 건드리지 말고 복제한 venv 에 설치 |
| 배치 1 에서 W8A8 이 느려짐 | 예상된 결과일 수 있음. 측정값 그대로 기록 |
| compile 없이 정수 커널 이점이 안 보임 | compile 켬/끔 둘 다 측정 |
| 4070 Ti 를 다른 사람이 같이 씀 | 측정 전 `nvidia-smi` 확인, 지연은 여러 번 재서 중앙값 |
| SmolVLA 내부 일부 층이 torchao 와 호환 안 됨 | `--quant-skip` 으로 제외하고 어떤 층을 뺐는지 기록 |
| 오프라인에서는 통과했는데 주행에서 무너짐 | 이 경우가 가장 중요한 결과다. 2단계를 생략하지 않는다 |
