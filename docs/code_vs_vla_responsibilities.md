## 0. 소유권 원칙 한 장

운동(조향·속도)을 실제로 만드는 주체 기준으로 보면 이 시스템의 상태는
정확히 둘뿐이다:

| 모드 | `/cmd_vel`을 만드는 주체 | 코드의 역할 |
|---|---|---|
| VLA 주행 (순항·존 주행·회피 중) | **SmolVLA 정책** (30스텝 행동 청크) | 문장 공급, 청크 이어붙이기, 감시 |
| 직행(최단거리) | navigator의 pure pursuit (코드) | VLA는 `""`로 침묵 |

VLA 주행 중에 코드는 **절대 Twist를 직접 내지 않는다.** 코드의 개입
수단은 단 하나, `/vla/instruction`의 문장 교체다. "회피해라"도, "감속해라"
도, "멈춰라"(빈 문장 = 큐 flush)도 전부 문장이다.

## 1. 파이프라인 전체 — 단계별 주체

채팅 입력부터 바퀴까지, 순서대로:

| 단계 | 하는 일 | 주체 | 구현 |
|---|---|---|---|
| 자연어 이해 | "천천히 안쪽 차선으로" → {action, lane, speed} 구조화 | **LLM(qwen) + 규칙 폴백** | chat_gui `parse_command` (스키마 강제) |
| 문장 렌더링 | 구조화 결과 → 학습된 정형 문장 "Start driving in the inner lane, slowly." | **코드** | `_vla_cruise_sentence` — 코퍼스 문장 뱅크와 일치해야 정책이 알아듣는다 |
| 관측 공급 | 카메라 프레임 + 상태를 정책 서버로 | 코드 | vla_bridge (JPEG 인코딩, ZMQ) |
| **행동 생성** | (이미지, 문장, 상태) → 30스텝 [dx, dy, dyaw] | **SmolVLA (학습)** | 정책 서버(랩서버 4070Ti), flow matching action expert |
| 청크 실행 | 30스텝을 10Hz로 재생, 새 청크를 선형 크로스페이드로 스플라이스 | 코드 | vla_bridge `splice` — 없으면 청크 경계마다 조향 트월치 |
| 안전 감시 | 청크 기아·지연 시 정지(워치독), 속도 상한 | 코드 | vla_bridge watchdog/캡 |
| Ackermann 변환 | Twist → 조향각/구동 명령 | 코드 | ackermann_cmd_adapter |

## 2. 기능별 소유권 — "누가 배웠고 누가 설계됐나"

### VLA(SmolVLA)가 **학습으로** 하는 일

전부 행동 복제 코퍼스(v3~v6)에서 나온 능력이다:

- **차선 유지** — 픽셀만으로. 차선 인식 모듈 없음 (zero lane-touch 실증).
- **문장의 차선 선택** — "inner/outer lane"에 따라 lane1/lane2 주행.
  같은 위치에서 문장만 바꾸면 궤적이 갈라진다(반사실 실측).
- **문장의 속도 티어** — slowly / normal / fast가 실제 속도 프로파일을
  바꾼다(라벨에 말한 속도만 학습시킨 slot 정책 덕).
- **차선 변경 기동** — ring-lane 반사실 쌍(같은 시작, 다른 차선 문장)
  으로 학습. 회피의 "몸놀림"이 바로 이것.
- **곡선 감속·재가속** — 코스 기하에 대한 반응.
- **(창발) 전방 차량 앞 제동** — 회피 코퍼스를 학습한 적이 없는데도
  장애물 3~5m에서 스스로 멈춘다. 16회 트라이얼 충돌 0의 절반은 이
  창발적 조심성 덕이고, 동시에 "근접에서 재출발 거부"라는 한계이기도
  하다(§4).

### 코드가 **설계로** 하는 일

| 기능 | 왜 코드인가 (핵심 근거) |
|---|---|
| 자연어→정형 문장 (qwen 파서 + 렌더) | 정책은 코퍼스 문장 분포만 안다. 자유 한국어를 그대로 넣으면 OOD |
| 청크 스플라이싱·워치독·속도 캡 | 실시간 제어 배관. 학습 대상이 아니라 신뢰성 요건 |
| **존 도착 판정** (navigator 좌표 감시) | 트랙이 시각적으로 균질해 카메라 정책은 자기위치를 원리적으로 모름 (T2/T3 구분 불가, 실측 확정) |
| **최단거리 직행** (pure pursuit) | 같은 이유 + 직행 학습 시도(v8)가 존 그라운딩 실패로 위임 결정 |
| **회피 의사결정** (감독 상태기계) | 트리거·차선 특정·복귀 타이밍. VLM은 "보인다"만 정확하고 차선 귀속 불가(실측), 정확한 기하는 좌표(레지스트리+gz pose+호길이)가 담당 |
| 장면 목격 (qwen2.5-VL) | 500M 정책은 말하는 출력구가 없고 설명 라벨도 없음 (§역할 문서 참조) |
| 내레이션·판단 패널 | 데모 가독성. 제어에 관여하지 않는 관측 전용 |

### 경계 사례 — "반은 코드, 반은 VLA"

- **회피**: 판단(언제·어느 차선) = 코드, 기동(조향) = VLA. 코드의 출력은
  문장 하나다.
- **존 주행**("go to T2"): 주행 = VLA(순항 문장), 도착·감속 타이밍 =
  navigator 좌표 감시(코드가 접근 시 slowly 문장으로 갈아끼우고 도착 시
  `""`).
- **회피 중 감속**: 감속 판단 = 코드, 실제 감속 = 정책이 "slowly" 문장에
  학습된 대로 반응.

## 3. 사고 실험 — 하나를 빼면 무엇이 무너지나

- **VLA를 빼면**: 차선 유지·차선 변경·속도 제어가 전부 사라진다. 감독이
  아무리 옳은 문장을 내도 듣는 주체가 없다. (구식 YOLO 스택으로 대체는
  가능하나 그건 다른 시스템이다.)
- **감독 코드를 빼면**: 차는 잘 달리지만 장애물 앞에서 (운 좋으면) 창발
  제동으로 멈춰서 끝난다. 회피·존 도착·직행이 없다.
- **qwen(해설·파서)을 빼면**: 주행은 그대로 간다(실측 — 터널이 죽어도
  주행 유지). 자연어 입력이 규칙 파서 폴백으로 좁아지고 내레이션이
  템플릿으로 내려갈 뿐.

이 비대칭이 시스템의 정체성이다: **운동 지능은 학습(VLA), 임무 논리는
설계(코드), 언어·장면 이해는 기성 LLM 임대.**

## 4. 현재 경계선과 이동 계획

지금 코드에 있는 것 중 **데이터로 VLA에 넘길 예정**인 것:

- 회피 기동의 시작·복귀(현 감독 담당) → **v9 회피 코퍼스**(오라클 위빙
  시연)를 학습하면 정책이 장애물을 보고 스스로 피하고, 감독은 판단자에서
  안전 감시자로 물러난다. 근접 재출발 거부(트라이얼의 안전 정지 케이스)
  도 같은 데이터로 풀린다.

코드에 **남는 것이 옳은** 것: 존 좌표 판정(시각적으로 불가능), 워치독
(안전 요건), 문장 렌더링(인터페이스 규약). 실차 전이 시 레지스트리
자리에는 LiDAR 검출이 들어간다.

## 5. 발표용 한 줄

> 바퀴를 움직이는 지능은 전부 픽셀과 문장으로 학습된 SmolVLA이고, 코드는
> 그 모델에게 "무엇을 하라고 말할지"와 "말이 통하지 않는 상황(좌표 판정,
> 안전 정지)"만 담당한다.
