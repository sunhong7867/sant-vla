# 장애물 회피 설계 — 무엇이 코드이고 무엇이 VLA인가

작성 2026-08-28. 구현: `chat_gui_node.py`의 회피 감독(`_avoid_check` 일대),
시험: `tools/eval/avoidance_trial.py`. 변경 이력·실측 근거는
`docs/ver/20260828_1617_obstacle-avoidance-and-reasoning-fixes.md`.

### 2026-09-10: 회피 후 옆 차선 차량에 의한 오정지 수정

미션1 첫 장애물 회피 후 좌표상 ego=lane1, 전방 장애물=lane2였지만,
YOLO는 화면 오른쪽 차량을 `lane1_car`(신뢰도 약 0.85, 높이 151px)로
분류했다. VLM은 false/far였고 `avoid_source=vision`이었다. YOLO 분기에
좌표 차선 검증이 없어 48px 임계만 넘으면 빈 회피 차선을 막힌 것으로
판단했다. 현재는 VLM과 YOLO 모두 최신 등록 장애물의 차선을 대조하며,
각 차선의 거리를 따로 확인한다. 등록되지 않은 장애물까지 좌표가 검증해
주는 것은 아니므로 이 보정은 현재 스폰 레지스트리 기반 시뮬레이션용이다.
좌표를 얻을 수 없으면 기존 영상 감지 대체 판단을 유지한다. 명시적으로
켜는 LiDAR(`lidar`/`any`)의 전방 정지 판단은 별도로 유지한다.

임시 정지에 빈 주행 지시를 발행하면 GUI 자신의 구독 콜백이 이를 사용자
정지로 받아 `idle`로 바꾸고 회피 상태를 지우는 결함도 있었다. 이제는
독립된 `/vla/avoidance_hold`를 사용해 모델 지시·회피 상태를 유지한다.
사용자가 정지를 누르면 재출발 예약도 해제한다. navigator/reset의
`/vla/hold`와는 별개이며, 어느 하나라도 켜져 있으면 정지한다.
회피 로그의 `source`와 `lane_s`에서 판단 근거와 차선별 거리를 확인할 수 있다.
아래 8월 시험 결과는 당시 모델·코드 기준의 기록이다.

## 0. 한 줄 요약 (자주 받은 질문에 대한 답)

**판단은 코드, 기동은 VLA다.** "언제, 어느 차선으로 피할지"를 결정하는
것은 서빙 계층의 감독 로직(코드)이고, 그 결정은 `/vla/instruction`의
**문장 교체**("Start driving in the inner lane, slowly.")로만 전달된다.
실제로 핸들을 꺾어 차선을 옮기는 행동은 SmolVLA 정책이 한다 — 코퍼스의
ring-lane 반사실 그룹(같은 시작 포즈, lane1/lane2 문장 쌍)으로 학습된
차선 추종·변경 능력이다. 감독은 Twist를 한 번도 직접 내지 않는다.

즉 "회피 기동을 코드로 짠 것"은 아니고, "회피 **의사결정**을 코드로 짜서
VLA에게 말로 시키는 것"이다. 이는 최단거리 직행(navigator 위임)과 함께
이 데모의 서빙 계층 합성(zero lane-touch 때 확립) 철학의 연장이다.
"주행은 SmolVLA인데 해설은 왜 qwen인가"라는 짝 질문은
[package_roles_and_pure_vla_rationale.md](package_roles_and_pure_vla_rationale.md) §4,
스택 전체의 코드/VLA 책임 지도는
[code_vs_vla_responsibilities.md](code_vs_vla_responsibilities.md) 참조.

## 1. 왜 이 구조인가 — 실측이 강제한 역할 분담

처음 시도는 "VLM이 보고 판단"이었다. 실측(2026-08-28, 로그 프레임
벤치마크)으로 7B VLM(qwen2.5vl, 384px)의 능력 경계가 그어졌다:

| VLM에게 시킨 것 | 결과 |
|---|---|
| 도로 위 장애물이 보이는가 (도형 열거 프롬프트) | **정확** (막힘 5/5, 클리어 5/5) |
| 거리감 (near/mid/far) | 대략만 맞음 (18m를 near로 보고한 사례) |
| 같은 차선인가 옆 차선인가 | **불가** — 9프레임 전부 'same' |
| 화면에서 좌/우 어느 쪽인가 | **불가** — 전부 'left' |
| 정면 근거리·곡선의 차량 | **사각지대** — 화면 절반 크기도 미검출 |

그래서 감지도 둘로 쪼갰다: **"보인다"는 VLM, "어디(어느 차선, 몇 m)"는
좌표**. 좌표는 스폰 레지스트리(`eval_out/demo/obstacles.json` — 장애물
스폰 성공 시에만 기록) + ego의 gz ground-truth 포즈(navigator 존 감시와
같은 인프라)로 계산한다. 거리는 유클리드가 아니라 **차선 경로를 따라 잰
호길이**다(컴팩트 링에서는 곡선 돌 때 반대편 직선의 차가 직선거리로
15~25m "전방"으로 잡히는 함정이 있었다).

백스톱: VLM 사각지대(정면 근거리·곡선) 때문에 좌표만으로도 지시 차선
17m 안이면 트리거한다. 보조로 best_cap의 lane1_car/lane2_car 검출
(bbox 높이 임계)도 트리거가 된다. LiDAR 검출기는 `avoid_source:=any`로
옵트인(기본은 vision — 카메라 중심 서사 유지).

## 2. 상태기계

```
CRUISE ──(경로 막힘: VLM 목격 + 좌표로 지시 차선 17m 이내
          / 또는 best_cap *_car)──▶ 회피: 장애물 반대 차선 문장 발행
                                     (slowly 티어 — 감지가 늦으므로 감속 겸행)
AVOID ─┬─(원래 차선의 장애물이 내 뒤 2m 이상)──▶ 복귀: 원래 차선 문장
       ├─(회피 차선에도 장애물, 원래 차선은 비었음)──▶ 즉시 원래 차선으로
       │                                              (지그재그 위빙)
       ├─(회피 차선 장애물 7m 이내 + 원래 차선도 막힘)──▶ 임시 정지(avoidance_hold)
       │      └─(시야 트임)──▶ 회피 차선 그대로 재출발
       └─(4초 정체 — 정책 프리즈)──▶ 같은 문장 재발행 kick (최대 2회)
```

수렴하는 데 필요했던 판정 규칙 셋 (전부 실주행 실패에서 역산):

- **판정 기준 차선**: 순항 중엔 **실제 차선**(gz 포즈 최근접 — 지시와
  실제가 갈라진 채 지시 차선만 보다 크래시), 회피 중엔 **지시 차선**
  (몸이 아직 옛 차선이라 실제 차선으로 보면 자기 회피 대상에 재차단).
- **정지선(7m)과 감지선(17m)의 분리**: 감지 즉시 정지하면 비어 있는
  10m를 남기고 서 버린다.
- **복귀는 시간이 아니라 기하**: "안 보인 지 N초"는 코를 돌리는 순간
  시야에서 사라지는 것과 구분이 안 된다. 장애물의 호길이 좌표가 내 뒤
  2m를 지나야 복귀.

파라미터(chat_gui ros params): `avoid_enable`, `avoid_source`
(vision/lidar/any), `avoid_coord_trigger_m`(17), `avoid_stop_m`(7),
`avoid_commit_s`(4, 전환 직후 판정 정지), `avoid_cooldown_s`(6),
`avoid_vlm_period`(0.6s), `avoid_range_m`(18), `avoid_obstacle_file`.

## 3. 폐루프 검증 결과 (2026-08-28, 자동 트라이얼 16회)

충돌 0. 실패 모드는 전부 안전 정지이고, 원인은 감독이 아니라 **정책**:
v6은 장애물 3~5m 근접에서 브레이크가 조향을 지배해, 차선 변경 지시를
다시 줘도 재출발하지 않는다(kick 무효). 재현:

```bash
./smolvla_demo.sh                                   # 장애물 3대 자동 스폰
python3 tools/eval/avoidance_trial.py --obstacles lane2:0.42   # 곡선 단일
python3 tools/eval/avoidance_trial.py --obstacles lane2:0.12,lane1:0.22 --start-frac 0.02
```

## 4. 한계와 로드맵

- 정책의 근접 재출발 거부(위) — 근본 해법은 **v9 회피 코퍼스**: 오라클
  (pure pursuit)이 스폰된 장애물을 위빙으로 통과하는 시연을 수집해
  정책이 회피 기동 자체를 학습하면, 이 감독은 "판단"에서 "안전 감시"로
  물러난다. 스폰 도구(`tools/spawn_avoid_obstacle.py`)와 트라이얼
  하네스가 수집·평가 인프라로 그대로 쓰인다. 로드맵의 반사실 게이트
  (차선변경 축)와 연결.
- 좌표 의존: 스폰 레지스트리가 없는 장애물(손으로 끌어다 놓은 도형)은
  차선 특정이 안 된다 — 그 경우 VLM near 폴백만 남는다. 실차에서는
  레지스트리 자리에 LiDAR 클러스터링/BEV 검출이 들어가는 구조.
- VLM 시야는 내레이션과 "보인다" 게이트로만 쓴다. 색 표현은 스폰 재질
  고유화 수정(012_deploy_lib) 이후 정확해진다.
